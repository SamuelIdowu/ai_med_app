## 1. Security findings & fixes (backend gateway)

### CRITICAL â€” fixed

- **Wildcard CORS in dev silently enabled in production** â€” `backend/src/app.ts` had a fallback branch bypassing origin checks when no env var was set. Removed; origin checking is now enforced in every environment.
- **Unauthenticated rate limiting keyed only by IP** â€” attacker with rotating IPs could exhaust limiter budgets against legitimate gateways. `backend/src/middleware/rateLimiter.ts` now keys authenticated requests by user id (`user:{userId}`) with IP fallback; the guest limiter is unchanged.
- **`/auth/check` admin scan** â€” called `listUsers()` (service-role user-table scan, O(users)) for an *availability check*, exposing the account-existence oracle on an unauthenticated pre-signup endpoint. Rewritten in `backend/src/routes/auth.ts` to a single indexed `.eq('email', â€¦)` lookup on `public.users` with normalized email.
- **RLS disabled on `audit_logs` + `incidents`** â€” both moderate/high tables were world-readable through the data API for any role with a grant. Fixed in `backend/src/db/migrations/011_audit_hardening.sql` (RLS enabled + restrictive policies) and applied live.
- **RLS enabled with no policies on `medical_profiles`/`photos`/`reports`** â€” deny-by-default was preventing direct accessâ€¦ but combined with default Supabase grants the GraphQL linter still reported discoverability. Policies added in 011; grants tightened again in 012 (below).

### HIGH â€” fixed

- **No input validation layer** â€” `backend/src/validation/` was an empty directory; routes/controllers passed raw user payloads into services, the Gemini API, and SQL filters. New dependency-free validators in `backend/src/validation/index.ts`:
  - `validateEmail` / `checkEmailAvailability` (used by `/auth/check` + register)
  - `validateUuidParam` â€” strict UUID (version 1-8, RFC-4122 variant) guard behind `readEncounterId` in `backend/src/controllers/encounterController.ts`, `getById`/`updateStatus`/`remove`, plus route-level guards in `backend/src/routes/encounters.ts` (also `fileName` validation on `/:id/photos`), `backend/src/routes/reports.ts` (`/:id/generate`, `/:id`), and `notificationController.markAsRead`
  - `validatePushToken` â€” Expo push-token shapes only, capped length, before anything is forwarded to the Expo API (`notificationController.ts`)
  - `validateChatMessage` + `validateChatHistory` â€” Gemini wire format (`role` âˆˆ user/model/assistant/system, `parts[].text` or `content`, â‰¤50 turns, â‰¤8000 chars) enforced in `backend/src/controllers/aiController.ts:chat`
- **Raw upstream error text leaked to clients** â€” `geminiService.ts` previously forwarded provider error strings (quota messages, malformed-payload details) straight into HTTP responses. Now static user-facing messages; details are logged server-side only.
- **`handle_new_user()` callable by anon/authenticated** â€” SECURITY DEFINER trigger function with default PUBLIC EXECUTE. 011 revoked anon/authenticated EXECUTE, but the lint persisted because **PUBLIC** also holds EXECUTE by default; migration 012 (`backend/src/db/migrations/012_graphql_exposure_hardening.sql`) revokes `PUBLIC, anon, authenticated`.
- **Mutable function `search_path`** â€” `update_updated_at_column`, `handle_new_user`, `match_guidelines` were definer functions with an attacker-influencable `search_path`. All three now pinned (`SET search_path = public, pg_temp`).
- **PostgREST/GraphQL table discovery (linter 0026/0027)** â€” client roles held broad SELECT grants. The backend gateway always uses the service-role connection (verified: every service call goes through `getSupabaseAdmin()`; the mobile app never reads tables directly except one realtime subscription), so 012 revokes SELECT from `anon` on **all** tables and from `authenticated` on all except `vital_readings`.

### MEDIUM â€” fixed

- **`testNotification` endpoint** validated nothing. Now requires a valid Expo push token, returns 404 in production, and bounds title/message length.
- **Notification `markAsRead`** â€” invalid id formats were passed to the DB layer; now UUID-guarded.

## 2. Security findings & fixes (Supabase live DB)

Both migrations were applied live via the management API during the audit, then committed as repo files:

- `011_audit_hardening.sql` â€” RLS + policies for `audit_logs`/`incidents`/`medical_profiles`/`photos`/`reports`; anon SELECT revokes on 12 PHI tables; `search_path` fixes; `handle_new_user` EXECUTE revokes.
- `012_graphql_exposure_hardening.sql` â€” full anon/authenticated revoke (except `vital_readings`), `vital_readings_owner_select` policy, `PUBLIC` EXECUTE revoke on `handle_new_user`.

**`vital_readings` detail:** the only direct-mobile-table access in the codebase is a Supabase Realtime `postgres_changes` subscription in `mobile/src/screens/HistoryScreen.tsx`. The table had RLS enabled with **zero policies**, so today that channel streams nothing (feature silently dead). 012 adds an owner-only SELECT policy (rows flow only to their owner) and keeps the `authenticated` SELECT grant for exactly this table. This is a deliberate, documented exception in the security linter output.

## 3. Infrastructure fixes

- **PHI database backups were unencrypted** â€” `.github/workflows/ops.yml`'s `db-backup` job dumped raw SQL to artifacts. Now: `pg_dump | openssl enc -aes-256-cbc -pbkdf2 -iter 200000 -pass env:BACKUP_PASSPHRASE`, artifact retention cut from 30 to **7 days**, restore instructions updated (new repo secret `BACKUP_PASSPHRASE` required).
- **CI lint gates were no-ops** â€” `.github/workflows/ci.yml` used `npm run lint --if-present` in both jobs, which silently skips if scripts drift. Replaced with hard `npm run lint` (verified passing locally: backend max-warnings 0, mobile max-warnings 0).
- **Predictable image/payload headers** â€” `cantValidate` earlier flagged that several routes never validated identifiers or file names; covered above.

## 5. Mobile fixes

### PHI vault fail-hard policy (CRITICAL)

`mobile/src/services/offlineStorage.ts`: the legacy AsyncStorage master-key fallback is removed. If SecureStore is unavailable the app now **throws** and degrades to memory-only persistence â€” plaintext PHI is never written to plain storage. Legacy AsyncStorage keys are migrated to the keystore and removed via `migrateLegacyKeyToStrongStorage()`; tests assert the memory-only behavior.

### Motion audit (review-animations skill) â€” all fixed

- `VoiceWaveformModal.tsx`: orphaned `pulseAnim` + its never-started animation effect removed (dead reactive work every render).
- `AIAnalysisScreen.tsx`: the determinate progress bar animated a **non-GPU width** layout property on the JS thread; now a `scaleX` transform with `transformOrigin: 'left center'`, `useNativeDriver: true`, and a zero-guard for the midpoint value.
- `OrganicFluidSphere.tsx`: three concurrent infinite Reanimated loops ran permanently even with `prefers-reduced-motion`; now gated on `AccessibilityInfo.isReduceMotionEnabled` + the `reduceMotionChanged` listener, and the animation effect no longer restarts on prop `size` changes. Test updated (shallow render).
- `SplashScreen.tsx`: brand reveal timings were 1.0â€“1.2s (sluggish); tightened to 450â€“500ms with an `Easing.out(Easing.cubic)` curve.

### Theme centralization (complete)

The design system (`mobile/src/theme/*`) existed but **~593 raw hex/rgba values** were hardcoded across 45 screens/components. All were migrated to tokens (final count outside theme/tests/icons: **0**):

- New value-preserving neutral ramp (`theme.colors.ramp.*`) and an `withAlpha(hex, a)` helper in `theme/colors.ts` so alpha overlays derive from tokens instead of bespoke rgba strings.
- Every status/accent color now references semantic tokens (`colors.status.emergency/warning/success/info`, `colors.primary.*`, `colors.palette.*`, `colors.chart.gridLine`, `colors.canvas.*`), which keeps them attached to the preset system for future re-theming.
- The only intentionally kept literals: the expo-notifications ARGB `lightColor` in `services/NotificationService.ts` (platform-specific format, cannot be a token expression).
- Legacy duplicate palette `mobile/src/constants/theme.ts` deleted; its backwards-compat test replaced with `ramp`/`withAlpha` coverage in `theme/__tests__/theme.test.ts`.

Migration was performed with a auditable codemod (two passes: value mapping + de-quoting of JSX attributes), followed by compile, lint, and the full mobile test suite.

### Network resilience

`mobile/src/services/networkRetry.ts` + `mobile/src/services/api.ts`: transient transport failures (`ERR_NETWORK`, `ETIMEDOUT`, `ECONNABORTED`, `ECONNREFUSED`, `ENOTFOUND`, `Network Error`) now auto-retry with exponential backoff (500msâ†’1sâ†’2s, 4s cap, â‰¤150ms jitter) â€” **GET/HEAD/OPTIONS only** (mutations are never auto-retried, preventing duplicate triage/report submissions).
